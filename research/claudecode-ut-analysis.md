# @ClaudeCode_UT 分析メモ

このファイルは、`research/claudecode-ut-primary.md` に保存した一次情報からの考察・仮説・示唆を保存する。

一次情報と分析を混ぜないため、Xから収集した事実・数値・URLは原則として `research/claudecode-ut-primary.md` に置く。

---

## 1. 現時点の結論

@ClaudeCode_UT は、単なるClaude Code情報アカウントではなく、以下の性質を持つメディアとして伸びている可能性が高い。

> 海外AI一次情報を、日本の非エンジニア / ビジネス読者向けに、痛みの言語化・概念命名・保存版記事・実務テンプレに変換するアカウント。

重要なのは、Claude Codeというテーマそのものではなく、伸びる情報の変換方法である。

---

## 2. 観測された勝ちパターン

5本の主要記事から、以下の型が繰り返し見える。

```text
読者の痛み
↓
それに名前をつける
↓
海外で伸びた一次情報・記事を持ってくる
↓
日本のビジネス現場に翻訳する
↓
Before / After で見せる
↓
具体的な手順・テンプレを出す
↓
最後にフォロー / LINE 導線
```

特に重要なのは、読者のモヤモヤに名前を付けている点である。

例：

- プロンプト税
- フォーマット税
- フォルダAI
- 判断の資産化
- Skillsはわざマシン

これは単なるノウハウ紹介より強い。

読者が「これは自分のことだ」と認識しやすくなるためである。

## 3. 記事別の分析

### 1. Re:ゼロから始めるClaude Code入門

#### 見えている型

- Claude CodeをChatGPTと同じ使い方にしてしまう痛みから入っている
- 「ブラウザAI」と「フォルダAI」という対比で視座転換している
- コーディング知識ゼロでも使える、と非エンジニアの恐怖を下げている
- 5ステップで導入できる形に落としている

#### 強い点

Claude Codeを単なる開発者向けツールではなく、リサーチ業務やビジネス業務に使える「フォルダAI」として再定義している。

これは、大山さん側でいうと、AIエージェントを「投稿生成ツール」ではなく「改善ループを回す仕組み」として再定義する余地がある。

---

### 2. AIに得意分野を持たせる20Skills

#### 見えている型

- 「AIに同じことを何回説明すればいいのか」という痛みから入る
- 海外でバズったSkills情報を日本語ビジネス読者向けに変換している
- 20Skillsの紹介にとどまらず、「プロンプトからSkills、パーソナルOSへ」という大きな流れに位置づけている
- 非エンジニア向けに、企画・調査・SNS投稿・会議録などの業務課題に再分類している

#### 強い点

単なるリスト記事ではなく、「プロンプトを毎回書く時代は終わった」という時代転換として見せている。

また、保存数が多い。これは、記事自体がテンプレ・スキル例を含み、後で使う価値が高いからだと考えられる。

---

### 3. Claude Code Skills徹底ガイド

#### 見えている型

- 非エンジニアの不安から入る
- Skillsをポケモンの「わざマシン」にたとえている
- SKILL.mdの仕組みを説明しつつ、本質を「判断の資産化」として再定義している
- 使い方だけでなく、失敗するSkills・改善方法まで扱っている

#### 強い点

抽象概念であるSkillsを、誰でも理解できる比喩に変換している。

この「比喩化」は、大山さんの発信でも使える。

例：

- AI運用は「自動販売機」ではなく「研究ノート」
- X運用AIは「投稿係」ではなく「実験助手」
- 投稿生成は「単発ガチャ」、改善ループは「育成ゲーム」

---

### 4. プロンプト税

#### 見えている型

- 毎回同じ説明を書き直す無駄に「プロンプト税」と名前をつけている
- Prompts → Projects → Skills という成長段階を作っている
- 「同じ指示を3回書いたらSkill化」という判定基準を示している
- プロンプトは取引、Skillsは投資という対比を使っている

#### 強い点

痛みへの命名が非常に強い。

「プロンプト税」という言葉は、読者が自分の無駄を認識するラベルになる。

大山さん側では、これをそのまま真似るのではなく、X運用・AIエージェント運用文脈に変換すべきである。

候補：

- 投稿生成税
- 自動化ごっこ税
- AI丸投げ税
- 検証不足税
- 学習しない運用税

---

### 5. MarkdownではなくHTMLを使うべき理由

#### 見えている型

- AI出力が長くて読まれない痛みから入っている
- 読まれないMarkdownのコストに「フォーマット税」と名前をつけている
- Anthropic内部の開発者発言を起点にして、トレンド性と権威性を出している
- 5つの業務シーンに変換している
- 最後は「フォーマット選びは作業ではなく判断」という上位概念に持っていっている

#### 強い点

単なるHTML出力テクニックではなく、「読まれる成果物を設計する」という判断の話にしている。

読者がClaude Codeに頼む内容だけでなく、出力形式を選ぶ能力が重要だと気づく構造になっている。

## 4. @ClaudeCode_UT のコンテンツ設計上の特徴

### 特徴1：海外バズの日本語ビジネス文脈化

海外で伸びたAI活用投稿や記事を起点にしている。

ただし、単なる翻訳ではなく、日本のビジネス読者の業務に置き換えている。

これにより、海外情報の新規性と、日本語読者の実用性を両立している。

### 特徴2：読者の痛みから始める

記事の冒頭は、ほぼ毎回、読者の具体的な痛みから始まる。

例：

- ChatGPTと同じ使い方をしてしまう
- AIに同じ説明を何度もしている
- ターミナルが怖い
- 長いAI出力を読んでいない
- ブックマークした情報を結局試していない

### 特徴3：概念命名が強い

単なる「こうすればいい」ではなく、痛みに名前をつけている。

名前がつくことで、読者が問題を認識しやすくなる。

### 特徴4：Before / Afterが明確

記事内では、Skillsがある世界線 / ない世界線、Markdown / HTML、Prompts / Skills など、対比が多い。

対比があるため、読者が変化後の状態を想像しやすい。

### 特徴5：保存価値が高い

「完全保存版」「徹底解説」「テンプレ」「5ステップ」「20Skills」など、後で見返す理由が強い。

ブックマーク数が高いのは、この保存価値が大きいと考えられる。

### 特徴6：最後に明確なフォロー導線がある

記事末尾で、アカウントが何を発信しているか、フォローすると何が得られるか、LINEで何が受け取れるかを明記している。

長文記事からフォロー / LINEに接続する導線が設計されている。

## 5. 大山さん側に転用できる抽象パターン

Claude CodeやSkillsというテーマをそのまま真似ると劣化コピーになる。

盗むべきはテーマではなく、構造である。

### 転用すべき構造

1. 読者の痛みを代弁する
2. 痛みに名前をつける
3. 海外 / 国内の一次情報を持ってくる
4. 自分で検証する
5. 日本語読者向けに実務文脈化する
6. Before / Afterで見せる
7. 手順・テンプレ・失敗例に落とす
8. 最後にアカウントのフォロー理由を明確にする

ポイントは、情報紹介だけでなく、検証を入れること。

大山さん側は、そこに「実際にやってみた検証」と「仮説行動の改善ループ」を加える。

## 7. 初期記事案

### 案1

```text
【検証開始】AIエージェントでX運用を自動化する前に知るべき「投稿生成税」の話
```

#### 狙い

AIでX投稿を作らせて満足してしまう状態に名前をつける。

#### 主張

本当に自動化すべきなのは投稿生成ではなく、仮説 → 投稿 → 反応 → 分析 → 改善のループである。

#### 構成案

1. AIでX投稿を作らせて満足していませんか？
2. でも、それは本当の自動化ではありません
3. 投稿を作るだけでは、なぜ伸びたかが積み上がらない
4. これを「投稿生成税」と呼ぶ
5. 本当に作るべきは、投稿生成AIではなく、仮説検証ループ
6. Claude Code / Codex / Obsidianでどう回すか
7. 30日間検証する
8. 結果・失敗・テンプレを公開する

### 案2

```text
【保存版】AIエージェント運用で最初に作るべき「検証ループ」の話
```

#### 狙い

AIエージェントを導入しても成果が出ない原因を、ツール不足ではなく運用ループ不足として定義する。

### 案3

```text
【実験】Claude CodeとCodexでX運用を分担させたら、どこまで自動化できるのか
```

#### 狙い

大山さんの実験そのものをコンテンツ化する。
